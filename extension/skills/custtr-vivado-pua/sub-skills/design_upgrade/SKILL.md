# Sub-Skill 2: Example Design Generation, Upgrade Process & Validation

Handles generating example designs for IPs that changed ports/signals/interfaces, building migration maps, applying the upgrade to a copy of the original design, and performing initial validation (elaboration, IP generation, simulation).

## When to Use

- After Sub-Skill 1 has classified IPs and identified those needing example designs
- IPs have port/signal/interface changes or have been replaced entirely
- Need to build a migration map from old to new IP connectivity
- Need to apply and validate the upgrade on a project copy

## Prerequisites

- Sub-Skill 1 completed: IP classification and changelog analysis available
- Target Vivado version installed and accessible
- Target device part number known
- Original project accessible (will not be modified)

## Procedure

### Phase 3: Example Design Generation for Changed IPs

1. **For each IP with port/signal/interface changes — create the IP example design:**

   ```tcl
   # Create a temporary project for example design generation
   create_project temp_ip_example <temp_path> -part <target_part>
   
   # Instantiate the IP with default or equivalent configuration
   create_ip -name <ip_name> -vendor xilinx.com -library ip -version <new_version> -module_name <ip_name>_inst
   
   # Configure the IP to match the intended use case
   set_property -dict [list \
     CONFIG.<prop1> {<value1>} \
     CONFIG.<prop2> {<value2>} \
   ] [get_ips <ip_name>_inst]
   
   # Generate the IP example design
   open_example_project -force -dir <temp_path>/example [get_ips <ip_name>_inst]
   ```

2. **Analyze the example design** — From the generated example design, extract:
   - Complete port list with directions and widths
   - Required clock and reset connections
   - Proper configuration properties for the target version
   - Correct bus interface connections and protocols
   - Any new mandatory signals or tie-off requirements
   - Reference connectivity patterns (how the IP connects to other logic)

3. **Build the migration map** — For each changed IP, document:

   | Old Port/Interface | New Port/Interface | Width | Notes |
   |---|---|---|---|
   | `old_signal_name` | `new_signal_name` | 32 → 64 | Width doubled |
   | `old_bus_intf` | (removed) | — | Replaced by individual ports |
   | (new) | `new_required_port` | 1 | Must tie to valid value |

### Phase 3.5: Custom RTL Module Migration

Custom RTL modules are user-written HDL files (Verilog, SystemVerilog, VHDL) that are NOT generated by Xilinx IP cores or Block Design automation. These include top-level wrappers, glue logic, custom datapaths, FSMs, testbenches, and any other hand-written design or verification source. This phase ensures they are explicitly carried forward to the target Vivado version **unchanged** (unless IP interface changes require modification, handled separately in Phase 4).

3a. **Inventory all custom RTL files** — Identify every user-written source file in the original project:

   ```tcl
   # List all source files in the project
   set all_sources [get_files -of_objects [get_filesets sources_1]]
   
   # List all simulation/testbench files
   set all_sim_sources [get_files -of_objects [get_filesets sim_1]]
   
   # Identify IP-generated files (these are NOT custom RTL)
   set ip_files [get_files -of_objects [get_ips]]
   
   # Custom RTL = all sources minus IP-generated files
   # Filter for HDL extensions: .v, .sv, .vhd, .vhdl
   foreach f $all_sources {
       set ext [file extension $f]
       if {$ext in {.v .sv .vhd .vhdl}} {
           if {[lsearch -exact $ip_files $f] == -1} {
               lappend custom_rtl_files $f
               puts "Custom RTL: $f"
           }
       }
   }
   ```

   Also check for files stored outside the project directory but referenced by the project (remote/shared sources):
   ```tcl
   foreach f $custom_rtl_files {
       if {![string match "*[get_property DIRECTORY [current_project]]*" $f]} {
           puts "WARNING: Remote custom RTL file: $f"
       }
   }
   ```

3b. **Classify custom RTL files** — Categorize each custom RTL file:

   | Category | Description | Examples |
   |----------|-------------|----------|
   | **Top-level wrapper** | Top module that instantiates IPs and custom logic | `top.sv`, `design_wrapper.v` |
   | **Custom logic modules** | User-designed functional blocks (FSMs, datapaths, controllers) | `axi_bridge.sv`, `packet_parser.v` |
   | **Glue/utility modules** | Small helpers (muxes, decoders, synchronizers, FIFOs) | `cdc_sync.sv`, `reset_bridge.vhd` |
   | **IP instantiation wrappers** | Thin wrappers around IP instances for port adaptation | `dcmac_wrapper.sv` |
   | **Testbenches** | Simulation-only verification files | `tb_top.sv`, `tb_packet_gen.sv` |
   | **Package/include files** | Parameter definitions, type packages, header files | `params_pkg.sv`, `defines.vh` |

3c. **Copy custom RTL files to upgraded project** — Copy all custom RTL files into the new project's `src/` directory, preserving relative directory structure:

   ```
   <project_name>_upgraded/
   ├── src/
   │   ├── rtl/                  # Design sources (synthesizable)
   │   │   ├── top.sv
   │   │   ├── custom_module_1.sv
   │   │   ├── custom_module_2.vhd
   │   │   └── packages/
   │   │       └── params_pkg.sv
   │   └── sim/                  # Testbench sources (simulation only)
   │       ├── tb_top.sv
   │       └── tb_helpers.sv
   ├── constraints/
   ├── ip/
   ├── bd/
   └── create_project.tcl
   ```

   TCL to copy and add files to the upgraded project:
   ```tcl
   # Copy custom RTL files preserving structure
   foreach f $custom_rtl_files {
       set rel_path [file tail $f]
       file copy -force $f <upgraded_project>/src/rtl/$rel_path
   }
   
   # Copy testbench files
   foreach f $custom_sim_files {
       set rel_path [file tail $f]
       file copy -force $f <upgraded_project>/src/sim/$rel_path
   }
   
   # Add design sources to the upgraded project
   add_files -fileset sources_1 [glob -nocomplain <upgraded_project>/src/rtl/*]
   
   # Add simulation sources to the upgraded project
   add_files -fileset sim_1 [glob -nocomplain <upgraded_project>/src/sim/*]
   
   # Set the correct top module
   set_property top <top_module_name> [get_filesets sources_1]
   set_property top <tb_top_module_name> [get_filesets sim_1]
   ```

3d. **Vivado version compatibility check** — Verify custom RTL is compatible with the target Vivado's synthesis/simulation engine:

   - **SystemVerilog language level** — Check for constructs that may behave differently or have changed support between versions (e.g., `unique case`, `priority if`, interface arrays, parameterized classes)
   - **VHDL standard** — Confirm the VHDL file type property matches the intended standard (VHDL 1993 vs. 2008):
     ```tcl
     # Check and set VHDL standard for migrated files
     foreach f [get_files -filter {FILE_TYPE == VHDL}] {
         set_property FILE_TYPE {VHDL 2008} $f  ;# or {VHDL} for VHDL-93
     }
     ```
   - **Synthesis directives** — Check for Vivado-specific attributes/pragmas that may have changed:
     - `(* keep = "true" *)`, `(* dont_touch = "true" *)` — still supported but verify behavior
     - `(* mark_debug = "true" *)` — verify target version supports the same debug flow
     - `ASYNC_REG`, `SHREG_EXTRACT`, `USE_DSP` — verify attribute values are still valid
   - **Deprecated constructs** — Some older patterns may generate new warnings or errors:
     - Implicit wire declarations (removed in later SystemVerilog tools)
     - Non-ANSI port declarations in certain contexts
     - `initial` blocks in synthesizable code (behavioral differences possible)

3e. **Verify file properties and library assignments** — Ensure all custom RTL files retain their correct properties:

   ```tcl
   # Verify file properties are set correctly
   foreach f [get_files -of_objects [get_filesets sources_1] -filter {IS_GENERATED == 0}] {
       puts "[get_property FILE_TYPE $f] | [get_property LIBRARY $f] | $f"
   }
   
   # Set library assignments if the original project used non-default libraries
   # (common in multi-library VHDL designs)
   set_property LIBRARY <lib_name> [get_files <filename>.vhd]
   ```

3f. **Record custom RTL inventory** — Document all custom RTL files for traceability:

   | File | Type | Category | Library | Notes |
   |------|------|----------|---------|-------|
   | `top.sv` | SystemVerilog | Top wrapper | work | Instantiates all IPs |
   | `axi_bridge.sv` | SystemVerilog | Custom logic | work | AXI4-Lite bridge |
   | `params_pkg.sv` | SystemVerilog | Package | work | Global parameters |
   | `tb_top.sv` | SystemVerilog | Testbench | work | Top-level TB |

   This inventory is used in Phase 4 to identify which custom RTL files need modification due to IP port/interface changes, and in Phase 5 to validate that all files elaborate correctly.

### Phase 4: Apply Upgrade to Original Design

4. **Create upgraded project copy** — Never modify the original:
    ```
    <project_name>_upgraded/
    ├── create_project.tcl       # Upgraded build script
    ├── bd/                      # Upgraded block design scripts
    ├── src/                     # Modified RTL sources (if needed)
    ├── constraints/             # Updated constraints (if needed)
    └── ip/                      # Upgraded IP configurations
    ```

5. **Upgrade IPs in the design** — Apply changes based on category:

    - **Version bump only:** Upgrade in-place:
      ```tcl
      upgrade_ip [get_ips <ip_instance>]
      ```
    
    - **Config changes:** Upgrade and reconfigure:
      ```tcl
      upgrade_ip [get_ips <ip_instance>]
      set_property -dict [list CONFIG.<new_prop> {<value>}] [get_ips <ip_instance>]
      generate_target all [get_ips <ip_instance>]
      ```
    
    - **Port/signal/interface changes:** Apply migration map:
      - Update all `connect_bd_net` / `connect_bd_intf_net` calls with new port names
      - Add connections for new mandatory ports
      - Remove connections for deleted ports
      - Adjust data widths in connected logic (slicing, padding, or redesign)
      - Update RTL wrapper files that instantiate the IP

    - **IP replaced entirely:** Replace the old IP instance with the new IP, connecting per the example design pattern.

6. **Update Block Design TCL scripts** (if applicable):
    - Update `scripts_vivado_version` to target version
    - Update all VLNV strings
    - Update CONFIG properties
    - Update port/interface connections per migration map
    - Add/remove ports as needed
    - Update address maps if memory interfaces changed

7. **Update RTL sources** (if applicable):
    - Modify instantiation templates for changed IPs
    - Adjust signal declarations for width changes
    - Add/remove port connections in wrapper modules
    - Update any hardcoded constants tied to IP behavior

8. **Update constraints** (if applicable):
    - Update clock definitions if IP clock structure changed
    - Update pin assignments if IP-level pins changed
    - Add false paths or multicycle paths for new clock domains

### Phase 5: Initial Validation

9. **Syntax and elaboration check** — Verify the upgraded design elaborates without errors:
    ```tcl
    synth_design -rtl -name rtl_check -top <top_module>
    ```

10. **IP generation check** — Ensure all IPs generate successfully:
    ```tcl
    generate_target all [get_ips]
    ```

11. **Functional validation** — Verify design behavior:
    - If testbenches exist, run simulation on both old and upgraded designs:
      ```tcl
      launch_simulation -mode behavioral
      ```
    - Compare simulation waveforms/outputs between old and new designs
    - Verify key functional signals behave identically
    - Check that new IP features/ports are correctly driven

## Output Artifacts

- Migration maps for each changed IP (old → new port/interface mapping)
- Upgraded project directory with all modified sources
- **Custom RTL inventory** — complete list of all user-written HDL files carried to the upgraded project, with file type, category, library assignment, and any compatibility notes
- Example design references for each changed IP
- Elaboration/simulation pass confirmation
- List of any issues requiring manual resolution

## Key Principles

- **Example design is ground truth** — When an IP changes ports/config/interfaces, the example design generated by the target Vivado shows the correct usage
- **Never modify the original** — Always work on a copy; preserve the original for comparison and rollback
- **Width mismatches are critical** — A single-bit width mismatch can cause silent data corruption; verify every connection width
- **Clock domain changes require careful analysis** — If an IP moves clocks around, all downstream timing constraints must be updated
- **Validate by comparison** — The upgraded design must produce functionally equivalent results to the original
- **Custom RTL is carried unchanged** — User-written HDL files must be copied verbatim to the upgraded project. They are only modified if IP interface changes force port remapping in wrapper modules. Never silently drop custom source files during migration.

## Common Pitfalls

- **Forgetting to regenerate IP targets** after property changes — always call `generate_target all`
- **Assuming port names are stable** — even minor IP revisions can rename ports
- **Ignoring new mandatory ports** — new IP versions may expose ports that must be connected
- **Not checking address maps** — AXI address spaces often change between IP versions
- **Skipping simulation** — synthesis success does not guarantee functional correctness
- **Mixing IP versions** — all IPs in a design must be compatible with the single target Vivado version
- **Dropping custom RTL files during migration** — user-written HDL files not associated with an IP are easily overlooked; always inventory and explicitly copy them to the upgraded project
- **Losing file properties on custom RTL** — VHDL standard (93 vs. 2008), library assignments, and `IS_GLOBAL_INCLUDE` flags must be preserved when re-adding files to the new project
- **Not validating custom RTL against new synthesis engine** — newer Vivado versions may flag previously-silent issues (implicit nets, non-ANSI ports, deprecated pragmas) as errors
